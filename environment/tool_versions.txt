R — THREE MECHANISMS, NOT ONE
  The R environment is the least uniform part of this project. Three different
  mechanisms were used, and which one applies is visible in each job script's
  own header rather than inferable from the arm.

  1. Module stack
     R/4.4.1-gfbf-2023a with R-bundle-Bioconductor/3.19-foss-2023a-R-4.4.1.
     Most analyses, including all of the transcriptomics and epigenomics.

  2. Module stack with a user library preceding it
     R/4.3.1-foss-2022b with R_LIBS_USER=$HOME/R/mmuphin_lib.
     Depression microbiome only: mmuphin_correct, diversity_mdd, and the two
     env_setup scripts install_mmuphin and fix_ancombc_deps. MMUPHin did NOT
     run under conda; it ran here. This user library ahead of the module on the
     library path is why some packages resolve to Bioconductor 3.20 rather than
     the 3.19 module, as modules.txt notes.

  3. Conda, outside the module stack entirely
     See below.

CONDA
  Miniforge3/24.1.2-0
  Four project-local environments, in two projects. They are not one shared
  environment, and the autism and depression arms did not use the same one.

  microbiome_r   .../dissertation-autism/Microbiome/conda_envs/microbiome_r
                 ancombc2_scz, lodo_check

  ancombc        .../neuropsychiatric2/MDD/microbiome/conda_envs/ancombc
                 ancombc_mdd_conda, maaslin2_mdd, run_pathway_DA
                 Built by environment/env_setup/make_ancombc_env.sh — that
                 script builds this environment, not microbiome_r.

  picrust2       .../dissertation-autism/Microbiome/conda_envs/picrust2
                 picrust2_run (autism, schizophrenia)

  picrust2       .../neuropsychiatric2/MDD/microbiome/conda_envs/picrust2
                 run_picrust2 (depression) — same name, separate environment,
                 separate project directory

  Conda was used because ANCOM-BC2 and MaAsLin2 would not resolve against the
  Bioconductor module. This is the departure referred to in modules.txt. The
  consequence is that the autism and depression differential-abundance results
  were produced under separately built environments whose package versions were
  not pinned to each other; see the limitation noted in the top-level README.
